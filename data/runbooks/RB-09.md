# RB-09 · Reading the function's log

owner: platform team · as of 2026-10-20 · readers: everyone

## The command

`aws logs tail /aws/lambda/triage-api --since 15m --region us-east-1 --format short` shows the last fifteen minutes. Add `--follow` to watch calls land as you make them. Lines arrive a few seconds after the call, and the `REPORT` line arrives last. If the newest call is missing, run the command again.

## One call, line by line

`INIT_START` is written by the platform when a new sandbox starts: the cold start. `START RequestId: ...` is the call beginning; its id is the same one stored in the inference table's row. `INFERENCE {...}` is written by the function: the row as it was written. `END` is the call finishing. `REPORT RequestId: ... Duration ... Billed Duration ... Max Memory Used ... Init Duration` is what the call cost; `Init Duration` appears only on a cold start.

## Following one request

`aws logs filter-log-events --log-group-name /aws/lambda/triage-api --region us-east-1 --filter-pattern "REQUEST_ID" --query 'events[].message' --output text` with the id from the row or the `START` line.

## In the console

CloudWatch → Log groups → `/aws/lambda/triage-api` → the newest log stream. One stream per sandbox, so a cold start opens a new stream.
