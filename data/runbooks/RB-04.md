# RB-04 · The function hits its time limit

owner: platform team · as of 2026-10-19 · readers: everyone

## Symptom

The log shows `Task timed out after 3.00 seconds` (or whatever the limit is) and the caller receives a 502 from the API. The function did not return; the platform killed the process when the limit was reached, and nothing it was doing survived.

## Why

The time limit is process death. A model call takes one to three seconds warm and longer on a cold start, so a limit of three seconds kills most cold calls and some warm ones. The time limit is set when the function is deployed; the default in `deploy.sh` is 30 seconds.

## Fix

Redeploy with a limit that covers a cold start plus a slow model call: `./deploy.sh --timeout 30`. Never set it below 10 seconds for a function that calls the model. If the limit is already 30 and the function still times out, the model is not answering: check RB-01 and RB-07 before raising it further.

## Related

A request that is killed by the time limit leaves no `INFERENCE` line in the log and no row in the inference table, because the write happens after the model returns. Count the `Task timed out` lines to see how many calls were lost.
