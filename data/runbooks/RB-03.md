# RB-03 · The first call after a deploy is slow

owner: platform team · as of 2026-10-19 · readers: everyone

## Symptom

The first request after `./deploy.sh`, or the first request after a quiet period, takes three to five seconds. Later requests take about one second. The slow one is a cold start: a new sandbox had to load the runtime, import the SDK, and read the environment before it could run the handler.

## How to confirm

Look at the `REPORT` line in the function's log. A cold start has an `Init Duration` field; a warm invocation does not. The response body also carries `cold_start: true` and `init_ms`, the time the imports took.

## What helps

Keep imports at module level, so they happen once per sandbox and not once per request. Raise the memory with `./deploy.sh --memory 1024`: on this platform more memory is also more CPU, and the import time falls with it. Every sandbox is recycled after some minutes idle, so a service with one request an hour is cold on every request.

## What does not help

Calling the function from a warm-up timer. The timer keeps one sandbox warm; the second concurrent request still gets a cold one. Provisioned concurrency would fix it and is not available in the Learner Lab.
