# RB-13 · A score served at the request differs from the stored score

owner: data team · as of 2026-10-20 · readers: everyone

## Symptom

`consistency.py` reports accounts whose score from `/score` differs from the score in last night's file by more than rounding.

## Causes, in order of likelihood

The weights file. The function and the batch run each carry `src/model/weights.json` with a `version` field; if the function was deployed from a different commit than the batch run, the two versions differ and so do the scores. Compare the `weights_version` field in the `/score` response with the one in the run's `run.json`.

The features. The batch run joins features as of the run's date; the request path reads the latest features. An account whose features changed today scores differently, and that is correct: the stored score is the account as of last night.

## Fix

Redeploy the function from the same commit as the batch run, then rerun `consistency.py`. Differences that remain should all be accounts whose features changed since the run.
