# RB-14 · deploy.sh fails

owner: platform team · as of 2026-10-21 · readers: everyone

## `sts get-caller-identity failed`

No live session, or credentials not pasted. RB-10.

## `Connection was closed` during the upload

The session's credentials were cancelled while the zip was uploading. Start a fresh session, paste credentials, run it again.

## The zip is too large

A deployment package must be under 50 MB zipped and 250 MB unpacked, including layers. `deploy.sh` prints both sizes after the build. The usual cause is a dependency that pulled in a large library: check `build/pkg` for anything you did not expect. The model weights for the runbook assistant are data, not a dependency, and are small.

## `Runtime.ImportModuleError` after a deploy

The package was built for the wrong platform. `deploy.sh` installs dependencies with `--python-platform x86_64-manylinux_2_28 --python-version 3.12`; if you installed into `build/pkg` by hand from a Mac, the compiled wheels are the Mac ones. Delete `build/` and run `deploy.sh` again.

## The function exists but the API does not

`deploy.sh` keeps an existing API and creates one only if none is called `triage-api`. If the API was deleted by `teardown.sh`, the next `deploy.sh` creates it again with a new URL; update `LAB_URL` in `.env`, which the script does for you.
