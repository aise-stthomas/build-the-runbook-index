# RB-15 · The model's output does not parse

owner: triage team · as of 2026-10-21 · readers: everyone

## What the parser expects

The triage step asks the model for one JSON object with `action`, `refund_amount` and `rationale`. The parser accepts the object alone or wrapped in a code fence. Anything else, such as `Sure! Here is my decision: refund it.`, is a parse failure and is recorded with `action: "error"`.

## What to do with a parse failure

Nothing clever. Count it. The harness reports the parse-failure rate per slice, and it is a rate like any other. A retry at temperature 0 changes the number you measure, so if you retry, record the retry as a second sample, not as a replacement.

## When the rate jumps

A parse-failure rate that was 2% and is now 15% with no change on your side means the vendor changed the model under you. Check the `model` field in the inference rows for a version change, and run the pinned golden set to confirm. Then decide whether to pin the previous version or adjust the prompt; either is a release.
