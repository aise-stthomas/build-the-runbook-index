# RB-05 · The API answers 401 or 403

owner: platform team · as of 2026-10-19 · readers: everyone

## 401 from the HTTP API

The route is protected by the shared token. The caller must send the header `x-lab-token` with the value of `LAB_TOKEN` from `.env`. In the Swagger page, click Authorize and paste the token; from curl, add `-H "x-lab-token: ..."`. A missing or wrong token gives `401 bad or missing x-lab-token header`. `GET /` and `/docs` are open and never need the token.

## 403 from a function URL

A bare function URL in the Learner Lab refuses anonymous requests with 403 regardless of its policy. That is why the lab puts an HTTP API in front of the function: the API is reachable with no signature. If you see 403, you are calling the function URL, not the API. Use the URL `deploy.sh` printed, which ends in `execute-api.us-east-1.amazonaws.com`.

## A classmate's API

Use their URL and their token, not yours. The token is checked by their function against their environment, so your token means nothing there.
