# RB-08 · The inference table has no rows

owner: data team · as of 2026-10-20 · readers: everyone

## Check the log first

Every call writes an `INFERENCE` line to the log before it tries the table. If the lines are there and the rows are not, the write failed and the log has a line beginning `{"level": "warn", "inference_table": ...}` saying why. Common reasons: the table name in the function's `INFERENCES_TABLE` variable does not match, or the LabRole was not attached at creation.

## Check the day

The partition key is the UTC day. After 7 p.m. in Minnesota it is already tomorrow in UTC, so `inferences.py` with no arguments shows an empty day. Use `uv run inferences.py --days 2`.

## Check the region

The table lives in `us-east-1`. A CLI query without `--region us-east-1` looks in whatever region your profile defaults to and finds nothing. The query itself: `aws dynamodb query --table-name triage-inferences --region us-east-1 --key-condition-expression "#d = :d" --expression-attribute-names '{"#d":"day"}' --expression-attribute-values '{":d":{"S":"2026-10-20"}}'`.

## What a row holds

What happened, never what was said: the time, the route, the build, cold start, latency, the action, the amount, whether the output parsed, and any error. Ticket text is not stored.
